# spec: 研究操作系统化

## 背景

情绪之道不能停留在板块资金看板。个人用户真正需要的是一个研究助手：不是盯价格，而是每天自动整理公开信息，把事件、产业链、公司和个人判断连接起来，并在未来帮助复盘。

## 用户故事

作为个人投资者，我希望平台能帮我整理每天发生的重要事件，判断它们影响哪些行业和公司，并保存我的研究过程。几个月后我回看时，能知道当初为什么关注这个方向，以及哪些判断需要修正。

## MVP 功能

### 1. 今日研究台

展示：

- 主要市场。
- 我的关注。
- AI 晨间简报。
- 今日重要事件。
- 待复盘观察。

### 2. 事件卡片

每条事件包含：

- 标题。
- 来源。
- 发布时间。
- 影响主题。
- 相关产业链节点。
- 相关公司。
- 证据等级。
- AI 摘要。

### 3. 产业链传导

用户点击事件后，系统展示：

```text
事件
-> 行业
-> 上游
-> 中游
-> 下游
-> 相关公司
-> 可能影响指标
```

### 4. 研究笔记

用户可以保存：

- 关注对象。
- 关注理由。
- 支持证据。
- 反对证据。
- 置信度。
- 待验证问题。
- 复盘日期。

### 5. 研究日报

系统生成日报：

- 今日发生了什么。
- 影响哪些行业。
- 哪些公司可能受益。
- 哪些只是市场情绪。
- 我的关注变化。
- 需要复盘的旧判断。

## 验收标准

- 首页有明确的“今日研究台”区域，而不仅是行情数据。
- 每条 AI 结论都能追溯到事件或数据。
- 用户可以把任一事件、板块、概念或个股保存为研究笔记。
- 研究笔记必须包含“为什么关注”和“后续验证什么”。
- 系统不能输出直接买卖建议。

## 数据模型草案

```json
{
  "noteId": "note_001",
  "createdAt": "2026-08-03T20:00:00+08:00",
  "targetType": "company",
  "targetName": "某公司",
  "reason": "受益于先进封装扩产和上游设备需求提升。",
  "supportingEvidence": ["公告扩产", "行业景气度提升"],
  "opposingEvidence": ["估值已高", "订单兑现周期不确定"],
  "confidence": 0.65,
  "reviewAt": "2026-09-03",
  "status": "open"
}
```

## 测试计划

- Unit：事件映射、证据分级、笔记结构校验、日报段落生成。
- Integration：保存笔记、读取笔记、生成日报。
- E2E：从事件卡片进入详情，保存研究笔记，再进入日报查看。
