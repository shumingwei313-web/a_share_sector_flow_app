# Agent Orchestration

情绪之道采用“研究闭环 + 多 Agent 编排”的产品结构。多 Agent 不是为了把系统做复杂，而是为了把金融研究中的不同认知任务拆开：先捕捉事实，再检索证据，再形成假设，再找反证，最后写成可复盘的记录。

## 分工

| Agent | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| Planner | 拆解研究任务，决定需要哪些证据 | 研究问题、对象、约束 | 任务计划、证据清单 |
| Collector | 捕捉公开信息和行情异动 | 新闻、公告、财报、电话会议、行情 | 原始信号流 |
| Retriever | 从资料库中检索证据 | Evidence Store、RAG 查询 | 可引用证据包 |
| Analyst | 形成初步研究判断 | 资金、人气、产业链、公司线索 | 假设与推理链 |
| Critic | 寻找反证和不确定性 | 假设、反证、风控规则 | 置信度、待验证问题 |
| Writer | 生成研究日报或汇报草稿 | 证据包、研究链、复盘记录 | 结构化报告 |
| Memory | 沉淀用户判断和复盘结果 | 用户笔记、证据状态、复盘日期 | 个人研究资产 |

## 模块映射

- 总览：展示市场情绪和当前研究对象，不直接暴露 Agent 编排。
- 捕捉：Collector 主导，Planner 提供任务边界。
- 资料库：Retriever 与 Memory 主导，把原始资料变成可引用证据。
- 研究链：Analyst 与 Critic 主导，把证据、反证和个人判断串起来。
- 研究日报：Writer 主导，调用 Retriever、Analyst、Memory 生成日报。

## 工具调用

短期前端演示阶段：

- Collector 使用前端缓存数据和公开接口样例。
- Retriever 使用本地 EvidenceRecord 列表模拟 RAG 命中。
- Memory 使用 localStorage 保存用户研究笔记。
- Writer 通过研究助理弹窗生成结构化草稿。

稳定上线阶段：

- A 股数据：AKShare 服务化，或通过 mcp-aktools/stock-sdk 进入数据层。
- 美股资料：financial-datasets/mcp-server 或其他金融数据 MCP。
- RAG：将新闻、公告、财报、电话会议、研报摘要转成 EvidenceRecord 后入库。
- 记忆：从 localStorage 迁移到用户级数据库，保留研究对象、假设、反证、复盘日期。

## 降级策略

- MCP 不可用：回退到缓存数据，并标注数据状态。
- LLM 不可用：返回证据整理模板，不生成确定结论。
- RAG 命中不足：要求补充资料来源，而不是强行生成观点。
- 证据冲突：Critic 提高不确定性提示，降低置信度。

## 产品原则

情绪之道不替用户做投资决策。Agent 的价值是减少重复整理、保留研究过程、帮助用户发现反证，并把每天的观察沉淀为可复盘的研究资产。
